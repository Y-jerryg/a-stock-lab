# 两个雷达修复验收记录（2026-09-15）

日常操作请阅读 [完整使用指南](user-guide.html)，或双击项目根目录的 `Start-Guide.cmd`。

## 发现的问题

- 用户夜间趋势扫描在北京时间 9 月 14 日 23:23 开始、15 日 04:18 结束，约 4 小时 55 分。
  数据库状态为 `completed_with_warnings`：请求 5,562、处理成功 5,549、失败 13、候选 1,270、
  强缩量 117。不是全部扫描失败，既有成功数据完整保留。
- 13 个失败中，12 个缺少目标交易日日线，1 个行情接口失败。缺少日线不等于已确认停牌。
- 已上传的趋势数据使用全市场规则和空反弹幅度上限，公网旧前端拒绝这种配置；
  本机列表还会重新按成交量排序，打乱关注度前 300 优先顺序。
- 公网尾盘网关及隧道容器处于停止状态，网页不能连接本机 API。
- 尾盘 9 月 14 日快照成功，380 个候选中的 68 个分时技术分析曾因数据源失败；
  AI 研究待处理表示尚未发起按需研究，不表示快照失败。
- 旧电脑窗口只使用进程退出状态，未提供明确的业务完成摘要。尚无足够证据将用户看到
  的“失败”精确归因于某一个 Windows 退出码问题。

## 已完成的修复

- 保留全市场扫描、最新 7～9 个收盘、最多 2 天反弹、末日严格最低、取消默认 1.5% 上限。
- 新前端兼容新旧规则，保留发布时的热门优先顺序，增加全结果搜索及每页 30 个候选。
- 命令行提供紧凑扫描摘要；Windows 操作脚本向控制窗口写入明确结果文件，区分已完成、
  部分失败但可用、真正失败和发布已提交。正常日志不再仅凭 stderr 判作业务失败。
- 修复 Windows PATH 存在多个 GitHub CLI 入口时的解析问题。
- 发布前检查 GitHub 上的网页规则版本，发现旧网页时先提示更新代码，不盲目上传不兼容结果。
- 控制窗口增加本机启动、运行状态、公网开关、尾盘入口及离线指南。
- 已恢复既有公网连接；已针对原尾盘工作流执行补抓，380 个技术分析全部成功，
  原始快照及历史时点保持不变，没有触发付费 AI。
