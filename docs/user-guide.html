1. 你每天实际要做什么

打开 Docker → 打开控制窗口 → 启动本机服务 → 查看或更新需要的板块

  1. 打开 Docker Desktop，等待引擎启动完成。仅打开 Docker 的窗口，不一定代表所有项目服务都已运行。
  2. 进入 D:\Dev\a-stock-lab，双击 Start-TrendRadar.cmd。它现在是两个雷达共用的电脑控制入口。
  3. 点击 启动本机服务，等待完成。它启动数据库、本机网站、后端和尾盘定时服务；不触发全市场趋势扫描，也不调用付费 AI。
  4. 需要看已有数据：点击 打开尾盘雷达或查看结果。不必为打开网页重新抓取。
  5. 需要当天尾盘数据：交易日北京时间 14:30 前保持电脑、Docker、网络运行，并让电脑不休眠。尾盘定时任务会自动执行。
  6. 需要更新趋势数据：建议交易日北京时间 15:45 后点击开始抓取。完成后先查看本机结果；要更新公网，再点击发布网站。
  7. 需要朋友访问尾盘和 AI：点击启动公网网站，等待连接成功和 GitHub Actions 部署完成，再分享原来的 Pages 地址。

所有市场时间均为北京时间（Asia/Shanghai）。如果电脑显示日本时间：14:30 北京时间是 15:30 日本时间，15:45 北京时间是 16:45 日本时间。网页里的“数据日期”是行情所属交易日，不一定是你操作电脑的日期。

只有首次安装、更新程序代码、或明确提示镜像/依赖缺失时，才需要点击准备本地环境重新构建。日常开机通常点启动本机服务即可。

2. 两个板块有什么区别

项目尾盘雷达趋势雷达
主要用途查看交易日 14:30 左右的市场快照、候选股、分时技术指标及按需 AI 研究。寻找截至最近已收盘交易日、最近 7～9 个交易日处于下降趋势的股票。
更新方式当前已启用交易日 14:30 定时服务。当前以电脑窗口手动抓取为准；并非只要 Docker 开着就每天自动更新。
公网如何取数据经 HTTPS 公网连接，读取你电脑上的后端和数据库。读取已上传到 GitHub Pages 的静态结果。
抓取后要发布吗公网连接正常时，刷新网页即可看到数据库新结果，不需要上传尾盘 JSON。需要点“发布网站”并等待 Actions 成功，公网才会更新。
电脑关机后公网尾盘数据及 AI 暂时不可用。别人仍能查看上次成功发布的结果和 K 线，但不会自动新增数据。

本机地址：尾盘雷达 · 趋势雷达。localhost 指的是当前访问者自己的电脑，不能把这个地址发给朋友使用。

4. 板块 1：尾盘雷达

如何看结果

  1. 点击“打开尾盘雷达”，先看数据日期、快照时间和候选数量。上次数据不会因为过了一天就自动变成今天的数据。
  2. 新快照使用涨幅 3%～5%（包含两端） 的 v2 规则。历史 v1 结果仍显示原来的 2%～3%，不会篡改旧数据。它与趋势雷达的连续下降规则不同。
  3. 可按股票名称/代码搜索，按板块、技术分析状态或 AI 研究状态筛选。
  4. 点击股票进入详情，查看快照价格、分时图、量价指标和技术分析。指标以保存的分析时点为准，不是实时交易终端。
  5. “技术分析成功”表示相应分时指标已经算好；“AI 待研究”通常表示还没有人确认并发起付费 AI，属于正常状态。

每天如何更新

交易日 14:30 由 worker 定时服务执行。电脑最好提前几分钟开机，确保服务已启动。采集和分析需要时间，14:30 刚到时尚未看到新记录不一定是故障。等完成后刷新，查看数据日期是否变为当天。

如果错过 14:30 的正式窗口，不能在晚上或周末重新“制造”当天 14:30 的全市场快照。保留旧数据并等待下一次正式采集。已有快照中的失败技术分析可以尝试恢复，恢复也必须沿用原分析时点。

部分股票分时接口失败时，其余股票仍然可看。不要把“部分成功”理解为快照和全部候选都失效。恢复失败项的命令见后面的故障处理。

尾盘详情里的 K 线与成交量

在尾盘候选列表点击股票，找到“5 分钟 K 线、成交量与日内特征”。上方是未复权 5 分钟蜡烛图，下方是成交量柱状图，红涨绿跌。鼠标悬停查看开盘、最高、最低、收盘、成交量和成交额；底部滑块可以缩放。

成交量坐标轴以“万股”显示，提示框以“股”显示。只展示页面标注的分析截止时间前已保存数据，不是实时行情或完整收盘后的日 K。技术分析失败、尚未完成或历史记录没有保存序列时，会显示无图提示，可按故障处理章节补抓。

5. 访客如何使用自己的 Key 做 AI 分析

  1. 打开尾盘候选股详情。公网访问需要你的电脑、Docker 和公网连接持续运行。
  2. 在 AI 研究区域填写访客自己的 OpenAI API Key。本机也使用同样操作，不需要网站运营者把自己的 Key 分给别人。
  3. 确认页面展示的研究对象和费用提示，勾选确认，再点击分析。只读股票页面和日常抓取不会自动调用付费 AI。
  4. 等待返回。运行中不要连续点击或反复重试；已有成功研究可能直接读取缓存。
  5. 如提示 Key 无效、权限或额度问题，检查该 Key 所属项目是否可以调用后端配置的模型。如提示网络/限流，稍后再试。失败记录需按页面按钮明确确认重试。

Key 经 HTTPS 发送到你电脑上的后端，由后端调用 OpenAI；不会写入网页发布包、应用数据库或浏览器持久存储。访客应信任网站运营者。不要把 Key 放进网址、聊天记录、代码或 GitHub 变量。

页面能打开不等于每一把 Key 都可调用模型。完整 AI 成功还取决于访客 Key 的权限、可用额度、模型服务和网络。分析输出会按现有研究记录机制保存；不要输入私人敏感信息。

6. 板块 2：趋势雷达

当前筛选逻辑

  • 扫描沪、深、北全部 A 股。关注度前 300 名只影响优先展示及金色标签，不限制入选范围；没有关注度排名的股票也会参与。
  • 截至最近已完成的交易日，按 9、8、7 个交易日依次检查，优先保留最长符合条件的区间。
  • 最多允许 2 天向上反弹，不限制单日反弹幅度；其余相邻收盘价必须下降，不接受平盘。
  • 最后收盘必须严格低于这段区间内此前所有收盘价，同时整体斜率向下。
  • 天数按区间内收盘价数量计算，7 天对应 6 次相邻比较。数据使用前复权日线。
  • 成交量低于此前基准期的设定比例时标为“强缩量”。这是独立标记，普通成交量的股票也可以入选。

新增：常驻抓取进程 + 默认 4 路并发

程序现在会同时处理最多 4 只股票，并复用已经加载 AKShare 的抓取进程。每个进程连续处理多次请求，每 250 次自动回收一次，扫描结束后关闭。单只请求超时或进程异常会重建对应进程并按规则重试，其他股票已保存的数据保留。

所有并发任务共用请求间隔，避免请求过密；缓存复用继续生效。新版控制窗口显示“已处理 X / 总数，4 路并发”，这是已经处理并保存的数量。抓取日志可能显示稍靠后的预取股票，遇到慢请求时完成进度会短暂停留。

  1. 本次已经更新本机镜像；关闭旧控制窗口后重新双击 Start-TrendRadar.cmd。
  2. Docker 正常运行后点击“开始抓取”，默认就是 4 路并发，不需要另开四个窗口。
  3. 等待结果，点击“查看结果”；需要更新公网时再点“发布网站”。

若以后在另一台电脑更新代码，先点一次“准备本地环境”来构建新版。需要降低并发可在 .env 设置 TREND_FETCH_WORKERS=1；默认 4、允许 1–8。实际耗时受网络、缓存和行情源限流影响，不能保证固定完成时间。

新增：本地数据复用与反弹分类

缓存已自动启用，保存在本机 Docker 的 PostgreSQL 数据卷。默认仅保留最近 29 个交易日（9 日趋势 + 20 日成交量基准）。同一交易日数据完整时直接复用；跨天更新会补缺失区间，并重查最近 3 条确认前复权一致。价格调整、数据源变化或缓存超过 7 天时会刷新计算窗口。程序自动清理窗口外缓存，不会删除历史扫描及候选股的原始证据。

全市场日更仍需获取各股票的新行情、股票名单和关注度。新浪备用源内部可能下载全历史再截取，因此不能承诺固定耗时；完整缓存的同日重复扫描可以省去日线请求。发布和打开详情始终无需重新抓取。尾盘雷达的当天 14:30 快照仍须当天采集，不能拿昨日数据替代。

  1. 打开趋势页面，紫色标签“反弹均 ≤ 2%”表示该股票趋势区间内每次反弹都不超过 2%，也包含没有反弹的股票。金色关注度、强缩量和该标签可以同时出现。
  2. 在“回调（反弹）天数”选择 0、1 或 2 天。这指收盘价高于前一交易日的天数。
  3. 在“反弹幅度类型”选择“反弹均 ≤ 2%（含无反弹）”，可单独查看该类；选择全部时，超过 2% 的入选股票仍显示。
  4. 这些筛选可以与强缩量、趋势天数、股票搜索组合使用。旧结果已有所需指标，无需为新标签重新抓取。

一次完整更新怎么操作

  1. 建议在交易日北京时间 15:45 之后点击“开始抓取”。15:15 之前程序使用上一已完成交易日；周末和节假日使用最近的实际交易日。
  2. 观察窗口进度，例如“正在处理 1234 / 5562”。全市场比原先 300 只耗时长；2026-09-14 这次实际约 4 小时 55 分钟，今后耗时随行情源、缓存和网络变化，不能保证固定时长。
  3. 运行中保持电脑唤醒、网络和 Docker 正常。个别股票失败会记录后继续；连续或大面积行情失败仍会触发整体停止。
  4. 看到“扫描完成：共……成功处理……失败……候选……”后，点击“查看结果”。成功处理包括未达到筛选条件的股票，所以候选数通常少于成功处理数。
  5. 网页每页显示 30 只，搜索名称或代码可跨全部结果查找。切换历史记录可查看原来的扫描；新规则不会悄悄重算旧记录。
  6. 点击股票名称或“查看 K 线与数据”，查看保存的日 K 线、MA5/10/20、成交量和每日行情表。图表阴影是入选区间，可以缩放查看。
  7. 确认结果后点击“发布网站”，等待 GitHub Actions 成功，再刷新公网网页。

2026-09-14 的全市场扫描已经完成：请求 5,562 只，成功处理 5,549 只，13 只未成功处理，保存 1,270 个候选。这个状态是 completed_with_warnings，不是整次失败。发布或网页出错时应先修复发布，不要因此再花数小时重新抓取。

7. 让其他人通过网站访问

现有网站：公网尾盘雷达 · 公网趋势雷达。给朋友分享这两个地址。

尾盘和 AI

  1. 本机两个板块先能打开。
  2. 点击控制窗口“启动公网网站”，或双击根目录 Start-PublicWebsite.cmd。
  3. 程序检查连接、更新后端地址并触发部署。打开它打印的 GitHub Actions 页面，等待最新相关工作流成功。
  4. 刷新 Pages 网站。电脑和 Docker 持续运行时，访客才能读取尾盘和提交 AI 请求。启动脚本完成后可以关闭其命令窗口，连接由容器维持。

这是临时 HTTPS 隧道，不要求购买云服务器。电脑重启、Docker 重启或隧道重连后，后端地址可能变化，需要重新运行启动入口并等待网站部署。朋友使用的 Pages 地址不变。当前方案不保证长久在线；固定域名隧道可以作为后续升级。

发布包大小与旧记录

新版先校验并导出每只候选股计算所需的 K 线，再将公开包控制在解压后 50 MiB 内。超过预算时优先保留最近的完整扫描；较旧扫描可能不再出现在公网历史选择中，但本机数据库仍完整保存。最新扫描不会被截掉部分股票。

如果遇到 Uncompressed bundle too large，更新代码后点击“准备本地环境”，再点击“发布网站”。已有数据可直接重新导出和发布，不需要重新抓取。

趋势结果

“发布网站”上传的是公开结果和候选股保存的 K 线，随后触发网页部署。部署完成后即使电脑关机，已发布趋势结果仍可查看。没有点击发布，本机新结果不会自动出现在 Pages。

代码更新和数据发布是两件事

修改了筛选参数结构或网页后，要先把代码同步到 GitHub 并部署，再发布新格式结果。本次入口增加了版本检查；提示“GitHub 网页版本落后”时，不要重抓股票，应先更新代码。日常只更新行情且代码没变，直接“抓取 → 发布网站”即可。

本机已安装 GitHub CLI 时，通常无需每天登录。若提示授权失效，在终端执行 gh auth login。仓库的 Settings → Pages → Source 应保持 GitHub Actions。

8. 如何判断完成、失败和发布状态

看到的状态真实含义下一步
扫描中 / running还在处理股票。看进度是否前进，保持电脑运行。
扫描成功 / success任务完整处理并保存。查看结果，需要公网更新就发布。
扫描完成（部分失败） / completed_with_warnings少量股票失败，成功数据及候选已保存。可以正常使用和发布。展开失败名单看具体股票。
failed本次任务遇到全局错误或超过失败阈值。查看原因；网页保留最近完成的结果，不能把旧结果当本次成功。
数据已上传 / 已提交网站部署已经触发 Actions，但还不能据此判定网站更新完成。等待对应工作流绿色成功，再刷新网页。
发布失败GitHub、网络、版本或构建问题；不等于抓取失败。修复发布问题后重发，不必重新扫描。
AI 待研究尚未发起付费分析。需要时在详情页自行输入 Key 并确认。

runtime/operator/*-error.log 是进程的标准错误输出文件，里面也包含正常的 INFO 日志和 Docker 提示；文件存在或里面出现“某只股票失败”，并不代表整次任务失败。新版窗口使用独立 *-result.json 报告显示最终结果。

9. 常见故障怎么处理

本机两个网页都打不开
  1. 确认 Docker 引擎启动完成。
  2. 打开控制窗口，点“启动本机服务”，再点“检查运行状态”。
  3. 应看到 postgres、backend、frontend 运行，尾盘定时还需要 worker。
  4. 用本机网址重新打开，必要时按 Ctrl+F5 强制刷新。
  5. 若服务镜像缺失或代码刚更新，再点“准备本地环境”。
本机正常，但公网尾盘打不开或不能 AI 分析

先点“启动公网网站”，等待连接检查和 Actions 成功。检查电脑是否休眠、断网，或 public-tunnel 是否停止。旧的临时隧道地址可能已失效，仅刷新浏览器不能修复失效的后端地址。

公网趋势没有数据，但我明明已经抓完了

先看本机趋势的数据日期和数量。本机有数据就不要重抓：点击“发布网站”，等待工作流成功。如果网页代码版本落后，先同步新代码；如果浏览器保留旧页面，强制刷新。确认打开的是正确的 Pages 地址，而不是旧收藏夹中的其他站点。

抓取有 13 只失败，是否需要重新跑全部股票

若最终是 completed_with_warnings，成功结果可以正常使用。missing_latest_session 表示该股票缺少目标日行情，可能是停牌或源未更新；provider_error 是行情源请求问题。不要强行拿更早的一根日线当作当天数据。

日志显示 stale_heat_data、scan_busy 或 market_data_failure_threshold

stale_heat_data：关注度数据还未更新到选定交易日，稍后重试。scan_busy：另一任务持有扫描锁，等待它完成，不要并发打开多个扫描。market_data_failure_threshold：失败过多或连续失败，检查行情源和网络后重试；已保存证据不会被删除。

尾盘快照有数据，但部分股票没有分时指标

通常是该股票的分时接口未成功，其他股票仍可看。已有快照可以恢复失败的技术分析，且不会重新执行成功项或调用 AI。需要沿用已有 workflow 的标识和原分析时点，见下面命令。历史行情源若已不提供对应数据，不能保证补齐。

网站已开，但某个 API Key 分析失败

先看具体错误：Key/权限/额度问题由 Key 持有人处理；超时、429 或服务不可用可稍后重试。不要连续触发付费请求。网站运营者不需要收集访客的 Key 来排查日志。

什么时候需要重新导出，而不是重新抓取

数据库已有完成结果，但本机网页文件丢失、导出失败、或需要补齐已保存的候选 K 线详情时，点“重新导出结果”。它不会更新行情日期，也不会把旧结果改按新规则重算。

10. 必要时使用的命令

平时优先使用按钮。以下命令在 PowerShell 中执行，先进入项目目录：

cd D:\Dev\a-stock-lab
# 查看所有容器状态
docker compose ps -a
# 启动本机服务（等价于按钮）
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/trend-radar-action.ps1 -Action Start
# 查看尾盘定时服务心跳
docker compose exec -T worker tail-radar worker-health --max-age-seconds 60
# 修复趋势输出，不重新抓行情
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/trend-radar-action.ps1 -Action Export
# 启动或停止公网
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/public-website.ps1 -Action Start
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/public-website.ps1 -Action Stop

尾盘失败技术项恢复

先取得已有快照对应的工作流标识，不要随意创建新的历史快照。下面从本机最新记录读取标识再恢复；它可能仍返回部分成功。

$run = Invoke-RestMethod http://localhost:8080/api/v1/tail-radar/runs/latest
$summary = Invoke-RestMethod "http://localhost:8080/api/v1/tail-radar/runs/$($run.run_id)/summary"
docker compose exec -T backend tail-radar resume --workflow-run-id $summary.workflow.workflow_run_id

可选：趋势每天自动抓取

目前默认手动。如果你以后确实要改为每个交易日 15:45 自动抓取，可执行以下命令。它仍不会自动发布到公网；“准备本地环境”会停止旧趋势定时容器，之后需要重新启用。

docker compose --profile trend up -d --build trend-worker
# 取消定时趋势抓取
docker compose --profile trend stop trend-worker

趋势定时每天最多尝试一次，失败后需手动重试。电脑错过当天运行时间，恢复后只按现有调度规则处理，不伪造过去的热度。

11. 关机、备份与长期运行

  • 想自动抓尾盘或让访客使用 AI，电脑必须开机、不休眠，Docker 与网络正常。显示器可以关闭。
  • 扫描过程中不要关闭 Docker、关机或重启正在运行任务的容器。关闭控制窗口会受到运行状态保护，但不能抵御系统关机。
  • 关闭公网用“停止公网网站”。停止不会删除数据库，公网趋势已发布数据仍保留。
  • 不要为了“重置程序”删除 Docker 的 postgres-data 卷，或执行 docker compose down -v，那会删除数据库数据。
  • 重要数据应备份 PostgreSQL 数据库和 runtime；仅复制项目代码或 GitHub 仓库不等于备份本机数据库。不要把数据库备份、runtime 或 .env 强行提交到 Git。
  • 临时隧道适合试用和小范围分享。需要长期稳定地址时，可以保留自己的电脑作为后端，再配置固定域名隧道；仍需维持电脑在线。
