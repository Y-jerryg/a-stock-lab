  也没有用这次诊断覆盖原分析。这个时间不包含全市场快照、正式编排与数据库写入；不能
  与原 27 分钟直接作为严格的性能对照，也不能保证交易时段的上游延迟相同。

### AI 与详情页面

- 原有 3 个候选累计 5 次 AI 尝试失败，错误为 `research_provider_api_error`，没有成功
  研究结果。历史持久化记录不包含具体拒绝参数，现有日志也不能恢复它；因此不能断言
  全部历史失败都由 Key、模型、超时或某一个参数导致。
- 修复 OpenAI SDK 错误元数据读取：SDK 通常已拆开 error 外层，原代码再次读取外层会
  丢失 code/param。现在兼容两种形状，仍不记录 Key、请求头或上游错误正文。
- 修复代理等待时间：原 Nginx 默认等待时间短于后端 90 秒配置。现设置 330 秒，覆盖
  后端允许的最大 300 秒配置，并禁止代理重放请求。
- 修复页面状态不更新：技术分析及 AI 进行中时每 5 秒 GET 刷新；不会因此重发付费 POST。
- 浏览器实际复现了详情页请求旧版本 JS 文件导致整页空白。现禁止缓存 HTML，缺失 JS
  返回 404；Service Worker 不再把 HTML 当资源缓存，并绕过导航 HTML 的 HTTP 缓存。
  页面新增错误边界及刷新入口。重载后已在真实浏览器确认分时图、字段与 Key 重试表单可见。
- 本机经过 Nginx 的请求验证：无 Key 返回 401，未确认费用返回 422；提供测试 Key 请求
  不存在的候选返回 404，均未执行付费调用。跨域预检允许 `X-OpenAI-API-Key`。
- 真实 SDK 加模拟 HTTP transport 的测试验证了 Key 进入 Authorization、严格 JSON Schema
  序列化、来源和结构化研究结果解析。没有用模拟成功结果污染数据库或页面。
- 后端可访问 OpenAI，未认证模型查询约 0.7 秒返回 401。但本机没有可用于本次验收的有效
  OpenAI Key，所以真实付费分析尚未验收，模型账户权限、配额以及真实请求参数是否被接受
  仍需在用户自己的账号下验证。Key 应在本机详情页输入，不应发送到聊天或提交到代码库。

模型和工具能力核对来源：[OpenAI 模型文档](https://developers.openai.com/api/docs/models/gpt-5.6-sol)、
[OpenAI Web Search 文档](https://developers.openai.com/api/docs/guides/tools-web-search)。
官方能力说明不能代替具体账号的调用验收。
